# 手机 / 微信 WebView 适配记录

日期：2026-10-24。

## 检查发现

- 片头缺少 error 和停滞退出逻辑；播放失败时隐藏的导航使用户缺少可见出口。
- 隐藏导航仅控制 opacity 和父级 pointer-events，但内部导航条仍 pointer-events:auto，会拦截顶部触摸。修复为片头期间 visibility:hidden 并禁止导航后代接收点击。
- 手机竖屏状态在挂载后才确认，原逻辑会先请求桌面片头；改为确认方向后只加载一次正确资源。移动片头为 H.264，moov 位于文件头，文件约 974KB；不是把所有问题归因于视频体积。
- 作品入口原先 preventDefault 后延迟 router.push，依赖 WebView 前端导航链；触摸还同时参与整屏切换，并在 touchstart 修改列表预览。
- 33 张平面详情图直接使用无损大图作为缩略预览，源图合计 37,154,474 字节。

上述为代码与模拟测试发现，不能据此断言已捕获用户手机上的全部触发条件。

## 修复

1. 增加独立“跳过开场”、视频 error 自动退出、10 秒无播放进度的退出兜底。微信桥准备好时重试播放；在手势内直接调用 play。触摸/微信端退出不再等待桌面淡出回调。
2. 分类入口保留真实 a href；微信或粗指针设备走原生页面导航，不依赖幕帘延时。分类列表详情和全局手机菜单同样使用浏览器导航。资源路径继续兼容 Pages basePath。
3. 从整屏手势中排除链接和按钮；列表预览只响应鼠标悬停，不在 touchstart 重绘。外链项目的名称也可进入详情，触摸目标至少 44px。
4. 手机停止自动下载背景循环视频与列表预览视频，以封面展示；离开首页后暂停视频。保留桌面视频效果。
5. 生成 33 张 640px 网页缩略图，合计 2,892,814 字节，减少约 92.2%。点击放大才使用原始无损 WebP；原始作品未改动。
6. 手机分类导航横向滚动，减轻 blur/backdrop-filter 和持续合成开销。dialog 不可用的旧内核直接打开原图。

## 验证方式与边界

- `node scripts/test-mobile-browser.mjs http://127.0.0.1:3000 ios` / `android`：隔离的 Chromium + 微信 UA + 触摸模拟，不连接用户浏览器，也不是 iOS WKWebView 或 Android X5 真机。
- 覆盖禁止自动播放、手动跳过、停滞自动退出、分类→项目详情触摸、缩略图/原图分离、放大/关闭，以及 320/390/430/768px 的分类区溢出检查。
- TypeScript、定向 ESLint、Pages/Sites/Vercel 构建检查。
- 全仓仍有本次范围之外的 React Hooks 规则问题，不将完整 ESLint 标记为通过。
- 微信 iPhone、微信 Android、低电量模式、弱网以及长时间切后台后的播放，仍需真机验收。不能保证浏览器允许自动播放；本次保证提供明确的播放/跳过/失败出口。

发布目标必须是 `beimuwz` / `https://www.beimudesign.top`，不是同账户下的 `beimu`。
